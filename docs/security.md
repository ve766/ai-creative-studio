# 安全、隐私与可靠性

## 1. 当前状态（v0.1.0）

- 无服务端、无用户账号、无外部服务，因此不存在服务端密钥、支付凭证或用户数据泄露面
- 项目数据仅保存在用户浏览器本地存储，不上传任何服务器
- 仓库中不含任何真实密钥；`.env.example` 仅列出变量名与用途

## 2. 密钥管理

- 所有密钥只存在于**服务端环境变量**或托管平台的密钥管理系统
- 绝不进入：前端代码、`NEXT_PUBLIC_*` 变量、Git 仓库、日志、错误上报
- 前端需要 AI 能力时，通过经过身份验证的服务端接口发起请求
- `.gitignore` 已排除 `.env`、`.env.local`、`.env.*.local`
- 泄露后的处置：立即轮换密钥，检查调用日志确认是否被滥用

## 3. 上传校验（已实现）

客户端（`packages/editor-core/src/uploads.ts`）：

| 检查 | 规则 |
| --- | --- |
| 空文件 | `size <= 0` 拒绝 |
| 大小 | 默认上限 20 MB |
| 类型 | 仅 `image/png`、`image/jpeg`、`image/webp` |
| 扩展名 | 必须与类型匹配（`.png` / `.jpg` / `.jpeg` / `.webp`） |
| 单边尺寸 | 上限 12000 px |
| 总像素 | 上限 4000 万 |

服务端（阶段 2 起）必须**重新校验**，并额外校验实际文件内容（magic bytes）而非仅信任 `Content-Type`。

## 4. 认证与授权（阶段 2 起）

- 认证：托管认证服务的会话令牌，httpOnly + Secure + SameSite
- 授权：每个资源访问都做所有权校验；越权返回 `NOT_FOUND`，不泄露资源存在性
- 数据库启用行级安全（RLS），服务端用受限角色访问
- `service_role` 密钥只用于服务端任务，绝不暴露给浏览器
- 前端传递的订阅状态、价格、额度一律忽略，全部由服务端重新计算

## 5. 输入校验

- 所有 API 请求体与查询参数经 Schema 校验（与 `packages/*-schema` 共用定义）
- 项目 JSON 在写入数据库前经 `@acs/project-schema` 校验
- 拒绝未知字段（严格模式）以避免参数污染
- 数值字段做范围限制（如 `opacity` 0–1、尺寸 > 0）

## 6. 文件名与路径安全

- 存储路径由服务端生成（UUID），不使用用户提供的文件名
- 用户文件名只作为展示用的 `name` 字段，渲染时转义
- 导出文件名在客户端清理非法字符（`[\\/:*?"<>|]`）

## 7. CORS 与会话

- 仅允许受信来源
- 不把会话令牌放在 localStorage
- 高风险的敏感操作要求二次确认

## 8. 日志脱敏

禁止记录：密钥、令牌、支付敏感数据、完整用户图片内容、不必要的个人内容。
允许记录：请求 ID、错误码、任务 ID、耗时、用量计数。

## 9. 第三方服务

- 接入前评估其图片留存与数据使用政策并记录于 `docs/decisions/`
- 未经用户明确授权不将设计上传第三方
- 对用户上传内容、版权声明与 AI 生成内容给出产品提示

## 10. 备份与恢复

- 托管数据库自动备份；定期验证恢复流程
- 对象存储启用版本控制与生命周期策略
- 删除策略：软删除 + 定期清理任务；用户可请求彻底删除

## 11. 可靠性

- 外部调用统一超时与有限重试
- 任务幂等（幂等键 + 唯一约束）
- 资源限制：图片尺寸、渲染资源、请求频率
- 失败必须显式暴露给用户，不静默降级为"成功"

## 12. 已知风险与待办

| 风险 | 现状 | 待办 |
| --- | --- | --- |
| 本地存储被清除导致项目丢失 | 已提示并提供 JSON 导出 | 云端同步 |
| 前端校验可被绕过 | 阶段 1 无服务端 | 服务端重新校验 |
| 无速率限制 | 无网络请求 | 阶段 2 引入 |
| 无审计日志 | 无敏感操作 | 阶段 2/7 引入 |
